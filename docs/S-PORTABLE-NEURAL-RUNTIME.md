# S v0.2.1: small neural inference without PyTorch

Purpose: remove the optional PyTorch dependency from **runtime tests of the
existing small checkpoint**, without retraining/replacing weights or claiming
improved intelligence. This is a bounded CPU reference implementation, not a
replacement for high-performance runtimes or support for arbitrary large models.

## Run from a current S checkout/installation

```sh
S model install-demo
S model configure-runtime --backend stdlib
S model probe --prompt "Request: Hello" --tokens 16
S develop application
```

In a source checkout use `python -m s_developer.cli` in place of `S`; on Windows
use `.\scripts\S.cmd`. In Termux the installed launcher is `~/.local/bin/S`.
The runtime test also appears in the Developer coding panel. Save a project draft,
check action consent, and select **Test neural runtime · 16 tokens**. It records
only probe identity/timing in that project's history. Prompt text is not appended
to probe audit records. Generated bytes are displayed as inert text/JSON, not
executed as source.

Output identifies `python-stdlib-f32`, the exact weight SHA-256, greedy token IDs,
time and `inference_completed`. That last field means calculations executed; it
does not establish correct answers, valid code or completed software. The bundled
checkpoint's previous neural code-format diagnostic remains failed.

## Actual compatibility boundary

No torch, numpy, safetensors package, external model, network call or pickle is
needed. The weights are the unchanged SBrain safetensors file. The restricted
reader follows the official [safetensors format](https://github.com/huggingface/safetensors#format)
for expected finite F32 vector/matrix tensors only. It rejects malformed headers,
duplicate keys, non-F32/unexpected shapes, invalid metadata/offsets, overlapping or
unindexed payload bytes, nonfinite weights and digest changes. It is not a
complete general-purpose safetensors implementation.

Limits: <=4 MB weights, dim<=64, <=2 layers, context<=256, <=8 attention heads;
1–64 prompt UTF-8 bytes; <=128 generated tokens for the explicitly selected
provider, <=32 for diagnostic requests; <=5-second default computation deadline
checked between bounded token steps. Unsupported larger/different checkpoints
are refused. No automatic external fallback is introduced. If the phone reaches
the time budget, try a shorter prompt or `--tokens 2`; phone latency is unmeasured.

The portable implementation reproduces embedding, RMSNorm, RoPE, grouped-query
causal attention, gated SiLU feed-forward and tied output projection. Incremental
cache positions stop at context exhaustion; it never silently reuses stale
context. Python floating-point arithmetic differs from PyTorch F32 arithmetic,
so equivalence is numerical within a declared tolerance, not bitwise identity.
Greedy decoding is deterministic; it is not the same sampling policy as the
existing stochastic PyTorch generation path.

## Verification

Tests compare actual PyTorch outputs for every prefix in ASCII and UTF-8 byte
inputs, and match 16 greedy token IDs. An initial 21-prefix measurement gave
maximum absolute logit error `5.091501314780089e-06`; regression tolerance is
`3e-4`. A Python subprocess using `-I -S` loads the original weights and generates
tokens while asserting neither torch nor numpy is imported. The no-dependency
wheel installation also executes a real probe. These establish host/package
runtime operation; physical Android performance still requires a phone probe.

Local suites: 94 app/portable/security/updater tests, 798 S-Brain tests and 24 UI
state tests passed. UI checks use fixtures, not automated browser rendering.
Prior real container build/repair evidence remains in merged PR #16; this runtime
does not remove Docker isolation or introduce host code execution.

## Updating the already installed phone

A fresh checkout can replace the managed launcher while retaining the database
at `~/.local/share/S/continuum.sqlite3`. Old launcher copies are retained. Keep
the new checkout in place. Stop the old S server with Ctrl+C before restarting
on the same port. If a native backend was explicitly selected earlier, setup
preserves it; choose stdlib with the command above when desired.

```sh
pkg install -y python git
s_runtime_dir="$(mktemp -d "$HOME/S-runtime-XXXXXX")" &&
git clone --depth 1 --branch main https://github.com/shiyamprimetrade-sketch/S.git "$s_runtime_dir/source" &&
python "$s_runtime_dir/source/scripts/install_termux.py" &&
"$HOME/.local/bin/S" model probe --tokens 16
```

This command is for use after this feature is integrated into main. Verify the
PR/commit first. No phone was remotely updated by the coding executor. A successful
phone probe closes the runtime-execution check only; general neural coding,
business acceptance and Android APK delivery remain separate unfinished work.
