# AxiomFlow Continuum — Teaching continuity checkpoint

**Origin:** Human-provided lessons from the independent computing / KEY26 learning sessions. Record them as research direction, not as scientifically verified conclusions.

## Why the project exists

The user wishes to continue their research partnership even if access to the current subscription or chat service ends. A portable, self-hosted conversation and experiment journal should preserve the method, evidence and lessons without requiring a remote AI API.

## User-taught principles

1. A keyboard exposes a set of symbols with enormous combinatorial potential. A finite alphabet permits arbitrarily long symbol sequences, though their physical storage still consumes resources.
2. Invent a new programming language from letters/words, where words can acquire functions and where relationships may be discovered through interaction and feedback.
3. Example: ABCA and CABA each have four letters. `4 → FOUR → 4`; `APPLE → FIVE → FOUR → 4` shows transformation via deterministic English naming and counting.
4. Explore retaining a generating rule rather than every generated sequence. Distinguish reconstructible patterns from truly unpredictable data.
5. Redefine software-level interfaces when useful; do not mistake changing a displayed label or reported capacity for new verified physical storage.
6. A terminal is an interface; success/error labels are conventions. An error can trigger diagnosis, alternative design, a measured retest and an evidence checkpoint.
7. The goal is an invention useful to humanity, with clear creator attribution and portable research data. Respect boundaries between SLICKK Mail, KEY26, AxiomFlow and other projects.

## Scientific method for inventions

For every claim: state **Goal**, **Proposed mechanism**, **What could disprove it**, **Test procedure**, **Observed evidence**, and **Status**. Use labels: Fact, Hypothesis, Simulation, Measured, Unverified. Never claim a real-world effect merely because a program prints `SUCCESS`.

## Continuation instructions for ANY future chat system

Read this document and imported history/notes first. Adopt a collaborative research role. Begin by restating the latest verified checkpoint, not all prior conversation. Preserve project boundaries and ask one relevant question when teaching is underway. Prioritize measurable work and user consent for consequential changes.

## Initial technical milestone

A self-contained Windows app with local AI inference, durable messages, separated projects, portable export and backups, and a word relationship explorer. Completion requires tests and an actual local-model conversation, not just code files.
