# Axiom Human Computer — invention charter (2026-11-09)

## Objective
Build a **complete, independent, human-like computer**, not merely a renamed command shell. The machine should perceive, remember, acquire concepts through interaction, reason about goals, discover and test new methods, act on the environment, and continue learning. The owner must be able to inspect and change its logic, preserve its history, and operate essential functionality offline.

The word **human-like** identifies functional design goals, not biological equivalence, consciousness, feelings, or personhood. Every claimed ability must pass objective tests.

## Nonnegotiable engineering principles derived from teacher–student dialogue

1. Meaning first: infer an objective without requiring magic phrases such as "think deeply".
2. One user action may orchestrate multiple verified internal operations. Optimize actual cost and fault rate, not merely labels.
3. A mismatch, uncertainty or failure is evidence for investigation, never silently renamed a success.
4. Names, symbols, programming languages, instruction sets, and interfaces are designs that can be replaced when tests justify it.
5. Preserve original teacher examples, generated simulations, hypotheses, failed attempts, and validated results as *different kinds* of data.
6. Allow new executable behaviors to be **learned from examples** and **checked on unseen examples**.
7. The user controls data, permissions, operating environment and checkpoints. Never modify unrelated projects.
8. Avoid cloud-only dependencies for core personal operation. A user-owned computer remains usable without a ChatGPT subscription.
9. Challenge arbitrary design limits; experimentally measure physical constraints rather than denying or assuming them.
10. Complete milestones with working artifacts and evidence. No invented scores or false claims of machine intelligence.

## Completion criteria for the full invention

- **Own boot path:** boots Axiom's own kernel on a virtual machine and then on a selected physical target without harming the existing OS.
- **Own execution:** own process scheduling, memory protection, persistent filesystem, fault recovery and device interface.
- **Own interaction:** local chat, command interface, desktop, accessible text and voice channels, and opt-in visual perception.
- **Own intelligence:** locally runs a model with documented weights/training data, learns from authorized teaching, recalls context, and generalizes to held-out tasks.
- **Own actions:** performs OS and application workflows from a user goal, with verification and permission gates.
- **Own continuity:** restarts and restores durable memory, code, policies and task checkpoints.
- **Own evidence:** independent benchmark suite tracks reasoning quality, accuracy, latency, memory, energy, crashes and recovery compared to a baseline.
- **Hardware independence:** defines public interfaces so custom FPGA and eventually custom hardware can replace commodity CPU/device modules.

These criteria are not yet met. Completion of a first module does not equal completion of the machine.
